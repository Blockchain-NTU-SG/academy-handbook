# Week N · Part N — Title

## Why this matters

Two or three sentences. What this unlocks, or what goes wrong without it. Written for
someone who has never opened a code editor. No jargon that hasn't been introduced yet.

Open by connecting to the previous Part. The Foundation should read as one continuous
story, not five separate modules.

## Learning objectives

By the end of this page you should be able to:

- Objective one
- Objective two
- Objective three

Three or four. Each one starts with a verb the member can actually demonstrate —
explain, send, deploy, compare — not "understand" or "be aware of".

## Core

Must understand. The main body — our own explanation, reorganised from the
sources listed in the frontmatter, not a list of links.

Any term used here is either defined here or was defined in an earlier Part.
Use a visual when structure, sequence or comparison is easier to see than
describe. Do not add diagrams or tables only to break up prose.

## Landscape

Should recognise and roughly explain. Things a member should be able to place
in the map without being able to build or analyse them.

Keep these short — a few lines each. Landscape is not assessed unless explicitly
required elsewhere.

## Guided walkthrough

Optional — use only when the learner is actually performing an action. Numbered
steps should each be a single action and state the expected observable result.

1. Step
2. Step
3. Step

State what the member should see after each step, so they can tell when something
has gone wrong rather than continuing with a broken setup.

## Worked example

Strongly encouraged for abstract Core concepts, but not mandatory where it would
be unnatural. Carry one concrete example through the explanation when it helps;
use real values and screenshots when appropriate.

## Analogy guidance

If an analogy helps, say what it explains and where it stops if extending it
further could mislead the learner.

## Further exploration

Optional depth. Links out, no points, clearly marked optional.

This is where advanced topics live — MEV, AMM maths, tokenomics, restaking,
account abstraction, ZK architecture and so on. They are deliberately not part
of compulsory Foundation.
